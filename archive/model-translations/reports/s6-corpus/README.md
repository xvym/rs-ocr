# S6 正式语料与未完成项

新的离线语料包已通过冻结中文库门槛，**S6 整体仍未完成**。完整首版语料、电视变量页及任意 Easy Chat 组合仍有缺口；没有把固定截图集通过改写成全游戏覆盖。机器可读结论见 [progress.json](progress.json)，逐项见 [remaining-gaps.csv](remaining-gaps.csv)。

当前包有 3,575 条词条记录、793 条当前可见单元、350 条沿用的完整静态记录和 410 条模板。词条混合逐作记录与明确共用记录，不能直接当作去重词汇数。完整源清单仍是 13,479 条，按游戏展开 25,410 条；其中 16,857 条尚未核定中文候选、1,451 条没有中文桥接，均包含首版之外或用途待定的材料，不能直接当作首版缺译率。与已审词条/子窗口关联也不表示整条源记录获批。

新增的主要证据：

- 148 个旧槽位单元累计排除 138 个错误解释、补回 9 个正确经验值解释；只剩 2 个含义一致的双打行号身份歧义。另编的 13 个名字边界、9 个经验值、8 个派出窗口及 9 个观察消息案例通过。全部来源候选证据仍为 766／769；3 项未完整片段没有补未来文字。
- [日版名字证据](japanese-name-evidence.json)：两份 ROM 的命名模板、初始化读取与光标上界共 48 个局部指令案例，确认本地玩家和宝可梦命名 UI 最长 5 字、盒名 8 字。字体可表示集合只是保守显示字符集，未声称每个字都能从命名键盘输入；外来/脚本昵称仍保留单独的保守显示预算。
- [Easy Chat 原生证据](easy-chat-native-evidence.json)：逐字节核验两作各 993 个原生词表项，另补齐 22 个类别标签，共审查 1,015 个词语/类别标签。日英词语是独立本地化，例 `あなたに` 不能按英文 SON 翻成“儿子”。词条只用于明确的词语选择器类型，不机械拼成整句。
- 两作各 100 条固定对战塔问候已按日版实际编码重建、逐句补译。日版记录步长为 20、姓名字段 3 字节、6 个词的字段位于 +6，与美版结构不同。受限执行原生词长查询、宽度分支及排版器，词复制叶函数使用已核验的原生表。200 条固定案例都采用 3 词×2 行；另有 4 条声明输入的压力案例核验超长改为 2 词×3 行并滚动的分支。压力案例不冒充真实问候或实机执行。
- 215 组逐作同文多译已有 [保存的决定](../../corpus/s6/homograph-reviews.json)：168 组审查共同含义、24 组姓名本地化冲突保留原文、23 组仍要求类型上下文。原文、全部候选和游戏适用范围保留，不按首条取值。完整当前页的共同含义删除英文/汉化扩写，不提前带出下一清屏页。
- 133 条电视/采访源记录已按日文逐页补译：229 个纯字面页进入包；170 个变量页继续等待调用点、完整值、名字片段及当前窗口规则核定；4 个“なし”占位不发布。姓名鉴定中的字形片段不能当完整名字查库；`WorldOfMastersText3` 的 `STR_VAR_2` 由地图名写入，中文是“在…捉到”，不能误作“用某球捉到”。

所有语义核对都由参与实现的模型完成，**非盲、非人工、非独立人员验收**。源码/地址对应、日版原生打印证据及中文语义决定分别保存。

## S7 交接格式

正式包位于 [outputs/s6-corpus/](../../outputs/s6-corpus/)。普通加载不读取 ROM、截图、答案、上游缓存或开发字体。隔离目录只复制包文件的加载检查已覆盖招式、回复量、完整名字和制品篡改拒绝；S7 Java 集成尚未实施。

| 文件/字段 | 用途 |
| --- | --- |
| `runtime.json`，`schemaVersion=2` | 可审资源及来源匹配所需的完整源记录/战斗模型；不含中文答案或截图编号。 |
| `lexicon` | 完整词条、类型、逐作/共用标记、原候选和模型决定；`typedOnly` 只能在明确类型下使用。 |
| `units` | 日文当前单元、中文、适用类型/游戏及原源文哈希。没有当前完整单元时不能用未来页填充。 |
| `templates` | 已保存中文格式及显式名字/数字/有限枚举/词条槽位；重复槽位逐次核对，保留全部有效分割，实质冲突回退。 |
| `events`、`namePolicy`、`compositionPolicy` | 已核定当前行动、名字类型优先级及可见字段组合。数值取本次输入，未知完整名字保留；没有会话身份学习。 |
| `sourceRecords`、`sourceTemplates` | 源记录候选和受限组合模型，来源命中不等于中文批准。 |
| `provenance.json` | 全量日英记录、原汉化候选、地址/结构桥接、原冲突及离线决定；未核候选不进入已审中文集合。 |
| `source-inventory.csv` | 每作全部源记录的保守状态。`has_reviewed_unit_or_term_not_whole_record_approval` 明确只说明有已审关联。 |
| `build-manifest.json` | 输入、实现及所有制品 SHA-256；固定输入变化应重新构建/核对，不能忽略哈希继续用旧证据。 |

`tools/s6_corpus_probe.mjs` 是 S6 库级可用性探针：使用保存的中文，不在线改写；锚定完整当前输入，类型/游戏过滤，所有兼容输出一致才提供中文。显示空白重排仅用于库级可用性，不替代 S7 的原始 OCR、来源/打印一致性、可靠界面、时序及身份处理。未知组件不会计作完整中文。FEEL 根据固定源码 `pokenav.c` 中 `MON_DATA_SHEEN` 的用途译为“饱食度”，与单个宝可方块的“细腻度/润滑度”区分。

构建与检查命令（Node.js 22+，无 npm 依赖，固定开发输入已恢复）：

```powershell
node tools/build_battle_source_templates.mjs
node tools/evaluate_source_matching.mjs
node tools/audit_source_bindings.mjs
node tools/build_s6_corpus.mjs
node tools/evaluate_s6_corpus.mjs --gate
node tools/test_source_matching.mjs
node tools/test_battle_source_matching.mjs
node tools/test_s6_corpus.mjs
node tools/audit_s6_progress.mjs
```

仅重新核验日版证据时需要两份固定 ROM、pokeruby 缓存及 Capstone：`python tools/verify_japanese_names.py`、`python tools/verify_easy_chat.py`。重新生成 Easy Chat 原生证据后，固定问候的证据哈希也须重新核定；普通构建不读取 ROM。
