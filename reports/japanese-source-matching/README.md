# 日文来源匹配器与实际 OCR 离线诊断

已建立独立来源检索入口，在固定的 **13,479 条日英记录及 27 条原生标签／符号来源**中检索日文，不再受 410 条正式中文静态记录的范围限制。原生标签来自已冻结并验证哈希的 ROM 提取资源，包括未出现在文本转储中的摘要页标题。输入为实际 OCR 原文、检测出的布局类型，以及可证明的字形候选；输出来源候选、窗口位置、变量捕获和中文资源状态。当前不发布中文，未接入 Java 桌面或实时会话。

## 当前结果

使用原 S3 已存档的真实 OCR 输出，共 456 张截图中的 579 个目标区域。保留严格 OCR 原文，包括两项 `へラクロス`；只有原生字体 3、像素距离 0 且实际保留对应候选的字符才允许 `へ／ヘ`、`0／O` 两种来源查询。60 个区域包含此类候选，所有候选均有诊断序列对应，没有未映射字形。

| 保持原始 769 个 OCR 跨度进行比较 | 有完整来源候选证据的跨度 |
| --- | ---: |
| 修复前：每个跨度直接查询 | 600／769 |
| 当前：布局／组成字段及战斗专用模型，每个组成文字都须有来源候选 | 766／769 |

原先 169 个缺口中补回 166 个，原 600 个命中跨度没有退化，只余 3 个未完成片段缺少完整候选证据。旧基线的输入、旧实现身份与单元范围单独保存，评估器核对固定 SHA-256，不通过扩大拆分分母制造同口径提升。“完整候选证据”不代表全部来源已唯一确认或中文可发布；新战斗模型另有 32 项来源／显示含义复核，不能外推为全量来源准确率。

当前运行时拆成 1,133 个字段／文本单元，1,130 个有候选；731 个为唯一来源候选且未使用槽位捕获，86 个为唯一模板来源候选，313 个有多个来源。另有 2 个片段线索和 1 个未匹配。576／579 区域至少一个单元有候选，576／579 区域全部文字单元有候选。这些是**候选可检索性**，不是全量来源正确率。

原 769 跨度、当前 1,133 个检索单元和中文验收的 770 个应翻译单元／778 个存档单元不能互换。原基线中的三张 PC 菜单由检测器同时保留 `pc_pokemon_menu`／`save_summary`；现仅在四行文字分别与完整、有序的 PC 源菜单记录一致时建立拆项假设，记录全部来源证据，不改写检测类型，也不使用答案中的区域类型。

1,035 个新检索单元的至少一个来源有中文候选，121 个的至少一个来源有已核对静态记录；这些都不等于当前窗口可发布中文。中文固定库基线仍为 **25／770，未通过**。148 个单元捕获到槽位，31 个存在同一来源内的多种绑定解释，未触发搜索截断。战斗专用模型通过有限词表排除了“把补助效果当作特性”“把招式名当作道具”等绑定；一般缓冲、计数和版本槽位仍未批准用于中文。

## 来源正确性证据

另行编写并冻结 [27 项来源复核](../../corpus/source-matching/reference.json)：依据原日文与固定源记录直接检查，涉及 29 个预期来源出现项，目前全部被检索到；其中 7 项完整类型词条检查了全部候选，其余只证明预期来源未遗漏，不把其他候选自动判为正确。

复核覆盖对白、清屏、前后滚动窗口、同文多脚本、PC、道具说明、姓名模板、战斗提示、物种／属性同文和字形候选。答案与源文本哈希独立存放，匹配器不读取答案、截图编号、中文预期或未来画面。复核和实现由同一模型完成，**非盲测、非独立人员或人工验收**；579 区域的全量正确来源、全部误候选及完整变量答案尚未逐项核定，因此全量来源准确率保持 `null`。

45 项自动检查覆盖原检索边界，并增加界面选项过滤、短模板、数字显示形式、姓名＋称呼、原生标签、组合字段、畸形行回退、PC 源菜单证据、合并战斗菜单拆项与 Safari 上下文、原 600 项不退化、原文跨度完整保留及报告逐字节重现。实际来源正确性的依据是单独的来源复核；自动检查通过不代表全游戏或全量来源通过。

另有 18 项战斗检查，涵盖 28 个升降形式、354 个招式与错误助词／句尾、昵称／前缀、必要换行、反例及一致性回退。原 27 项来源探针保持通过；新增 32 项战斗答案独立存放并绑定源文和输入哈希，但同样由实现模型编写，非盲、非人工。当前有 34 个文字单元的战斗显示含义一致，2 个仍含未解释的其他来源；其余不在本轮结构化事件范围内。显示含义一致可以与多个脚本来源并存，不强选脚本身份。

## 检索规则

- 原文和来源控制符均保留。基础排版投影仍区分数字宽度；来源显示投影另外允许 `０～９`、`Ｈ／Ｐ` 和 `／` 对应 OCR 的 ASCII 数字、`H／P` 和 `/`，逐候选标记是否使用。保留前导零、数字边界和捕获原值，不做 NFKC、其他字母、大小写、任意标点或假名替换。
- 将原语料 `\n`、`\r`、`\c` 分别解释为换行、滚动行和清屏边界，建立整段、一行与相邻两行来源窗口，保留段号、行号；不跨清屏拼接。自动折行与变量长度引起的真实布局仍待日版打印规则核对。
- 通常模板要求至少六个固定字符；完整单槽位模板允许四个固定字符，支持“[PLAYER]のパソコン”和“ゆけっ！[名字]！”等短模板。裸槽位仍禁止。仅允许姓名后接有限的 `くん／ちゃん` 称呼候选，其他相邻不透明缓冲仍不拆分。重复槽位须保持一致，多解全部保留，日版调用点与称呼语义保持未批准。
- 已知颜色、暂停、音效等非文字控制的省略仅形成明确标记的检索假设。定位、清除、字体、显示符号及未知控制不自动删除或吞成变量，75 条源记录暂不支持，清单保留原因。
- 已确定的目标游戏和显式词条类型可以过滤候选；未确定游戏时保留两作。来源唯一也不自动批准窗口对应中文，完整词条不覆盖其他兼容窗口或模板候选。
- 已观察到的相邻滚动窗口可以在显式会话、同一上下文键和连续序号下缩小来源；重新核对前一窗口的实际文本，不信任外部传入的候选编号。会话、上下文或序号不连续时不使用前文消歧。该能力目前只有构造回归，未接入真实连续帧。
- 独立菜单按检测布局拆项；背包／商店行只有实际数量、价格或 SEL 证据时才按道具名过滤，“关闭背包／取消”等界面选项正常检索。摘要页、招式／属性／PP、能力值、主人／ID、性格／相遇等级、经验值、树果两段说明、存档摘要、能量方块及状态图按专用规则查询组成文字；可见值与语法连接符另存为未批准字段，任何非空白字符都必须在原文跨度中保留。畸形行保持整行查询。
- `gOtherText_Ribbons00` 的计数覆盖单独建立来源假设，依据固定美版摘要页调用代码的结构线索；保留原源文 `げんざい　００こ`、当前数字和未批准状态，不将其他源记录中的字面数字自动当作变量，也不据此宣称日版调用点已验收。
- 任意未知字形、没有字形证据的错字、名字前缀和普通子串不用于确认来源。长度足够的静态片段可以产生单独线索，不能成为完整单元或直接发布中文。
- 战斗菜单四个选项保存在合并记录 `rs.common.battle_strings.BattleText_MenuOptions` 中，索引按源记录明确的两行双空格网格拆成单元，保留源记录、行和列。完整当前菜单匹配后，用其来源限定各项；只查询“にげる”而没有整菜单上下文时，保留普通战斗及 Safari 菜单两种来源。普通对白不按此规则拆词。

## 使用与复现

需要 Node.js 22+；固定语料已恢复时全部离线，无 npm 依赖。原有 `query_corpus.mjs` 保留完整值精确查询用途。

```powershell
# 普通完整日文及明确的词条类型。
node tools/resolve_japanese.mjs --japanese ピカチュウ --kind species
node tools/resolve_japanese.mjs --japanese ゴースト --kind type --game ruby
node tools/resolve_japanese.mjs --japanese パーソナル --kind native_label

# 批量输入真实 OCR、检测类型与字形证据；输出来源候选，不输出中文。
node tools/resolve_japanese.mjs --input requests.json --out resolved.json

# 使用已冻结的579个实际OCR区域复现诊断及来源复核。
node tools/evaluate_source_matching.mjs
node tools/test_source_matching.mjs
node tools/test_battle_source_matching.mjs
```

批量文件为数组，例如：

```json
[
  {"japanese":"ポケモンの とくせいに よっては\nわざの いりょくが かわったり","typeCandidates":["field_dialog"]},
  {"japanese":"すごいキズぐすり × 07","typeCandidates":["bag_list"]},
  {"japanese":"へラクロス","kind":"species","alternatives":[{"index":0,"raw":"へ","candidates":["へ","ヘ"],"font":3,"distance":0}]}
]
```

首次构建本基线时，`freeze_source_matching_inputs.mjs` 从 `.tools/s3-{gba,ngc}-raw.json` 校验源图哈希、检测框、OCR 和字符序列，导出可追溯的紧凑输入；`freeze_source_matching_review.mjs` 将手写来源判断与固定原文绑定；`freeze_source_matching_baseline.mjs` 冻结两份基线。普通复现只读已保存输入，无需这些本机缓存。冻结工具拒绝覆盖不同内容，修订答案须建立新的基线版本。
