# 日版战斗组合匹配

已实现混合方案：源数据维护模板、有限词表和组合规则，构建时展开普通能力升降及合法招式句式；固定文字较多的相关消息保留受类型约束的整段匹配。输出来源、当前可见名字及结构化显示含义，不发布中文。

[规则定义](../../corpus/battle-matching/rules.json)、[生成模板审阅表](../../outputs/battle-source-matching/templates.csv)、[生成资源](../../outputs/battle-source-matching/templates.json)、[构建身份](../../outputs/battle-source-matching/build-manifest.json)、[日版原生证据](japanese-evidence.json)、[32 项固定集复核](../japanese-source-matching/battle-review.json)、[检查结果](checks.json)。

## 实现范围

| 模型 | 数量 | 行为 |
| --- | ---: | --- |
| 普通升降 | 28 个显示形式，56 个来源绑定 | 7 种能力 × 普通／大幅升降；只留下当前名字变量，保留攻击方／防御方同文来源。 |
| 招式使用 | 354 个显示形式 | 每个有效 RS 招式 ID 只使用日版选择函数实际给出的助词和句尾。 |
| 其他相关模型 | 14 个 | 上下限、特性触发／阻止、复制／清除、引火、道具使用及特性复制；有限槽位受能力、特性、道具或训练家类别词表约束。 |
| 经验值 | 2 个 | 普通／额外措辞，按日版缓冲组成绑定当前名字及十进制数值。 |
| 派出／换入预告 | 8 个源记录、15 个窗口 | 完整当前行动子句；保留单／双打等价来源、源行号及未来清屏边界。 |
| 野生、捕获、奖金、回复与使用消息 | 11 个源记录、22 个窗口 | 复制名字、十进制数值和有限道具/场景招式；保留兼容首屏来源，不推断未来效果。 |

普通升降能返回 `event: stat_change`、能力、`delta` 和显示主体；`deltaBasis: displayed_wording` 表示消息措辞对应的升降，不推断实际战斗阶段、起始／最终能力值或达到边界后的实际变化量。招式使用返回 `moveId`、招式源记录和当前主体。其他消息分别返回自身事件，不把屏障、引火、状态异常或能力等级变化混为一类。

例如 `カイオーガの\nとくこうが あがった！` 同时匹配两个同文源记录，来源状态仍为多候选，但 `semanticResolution.status` 为 `consistent`，显示含义为“该名字的特攻上升”。未据此判定当前是攻击方还是防御方。

## 日版规则证据

固定美版源码保留了原日版招式助词／句尾分类表。构建没有直接将其当作日版事实：

1. 将四组、118 个 u16 条目与两份固定日版 rev0 ROM 逐字节比较，两作均唯一命中；记录表偏移和两处指针引用。
2. 对两作的原生助词、句尾选择函数执行受限 Thumb 指令解释，分别输入全部 354 个招式 ID，共核验 1,416 次选择。解释器只支持函数所需的指令和内存读，在调用 `StringCopy` 时记录实际源指针并停止；未知指令、地址、超过预算或错误调用立即失败。
3. 实际选中的日文字符字节与固定语料的助词／五种句尾对应；能力名称、变化描述及野生／对手前缀也保留日版字节位置和哈希证据。ROM 始终只读，生成资源不包含 ROM 字节。

统计升降来源及特性允许集合同时参考固定源记录、升降表和调用点，32 项现有原始日文另行复核。该证据不等于完整日版战斗脚本执行，也不验证所有队伍、联机和实机时序。

## 匹配与回退

[经验值专项证据](experience-evidence.json)核对两作原生消息表中的 13、329、330 号记录，并在已声明寄存器／RAM 输入下分别执行经验值缓冲写入块 32 次，共 64 次。原生块写出“名字＋句式片段”的 `B_BUFF1` 和数值 `B_BUFF2`；美版是第三个缓冲保存数值，不能直接套用。验证在调用准备消息函数时停止，不执行经验值计算、交换判断或完整打印器。`boostedWording` 只表示当前措辞，`experienceAmount` 为当前可见数字，不推断真实物种或玩家身份。

[9 个存档区域](../japanese-source-matching/experience-review.json)的来源／名字／数值复核全部通过；另对三个领取来源施加逐 qid 的完整道具／物种约束，证据强弱及未验证日版调用点见 [来源报告](../japanese-source-matching/README.md#经验值来源与数值专项)。它们不批准动态中文，也不改变 `variable-rules.json` 的全局待审状态。普通／额外句式只在保守的五位十进制预算内识别，拒绝前导零、符号、小数及不完整输入；词表外自定义领取字段保守回退。

- 正则以完整输入为边界；普通升降、招式和相关句式保留源记录中的必要换行，不能把另一条战斗从句跨行吞成名字。空格可按原有投影处理，未知字形不补全。
- 名字须由原生字体可表示字符组成，非空且在有界长度内。当前十字符限制是保守检索预算，不宣称日版命名 UI 支持十字符。名字不要求命中物种表，不推断实际物种或玩家身份。
- 保存完整主体原文、前缀原文、名字范围和未批准状态。前缀也可能属于自定义名字时显式标记，后续显示／身份处理不能把启发式拆分当成确定身份。
- 有限槽位不能接受任意文字，例如“ほじょこうか”不是特性名，“つるぎのまい”不是道具名；这些错误不再通过泛用缓冲匹配。
- 同一输入的全部匹配都参与含义一致性检查。来源不同而显示含义一致时保留全部来源并返回结构化含义；实质冲突返回 `conflict`；仍有未解释来源或搜索未完成则返回 `incomplete`，不选首条。
- `ポチは\nねがいごとを した！` 同时存在招式使用与 `BattleText_WishMade` 来源，当前完整来源语义尚未统一，因此保留 `incomplete`。所有 354 招式规则能够检索，不代表所有招式显示都已唯一消歧。
- `translation` 仍为 `null`，也没有改写 `rawOcr`、批准中文、学习玩家身份或接入 Java 实时窗口。

## 验证结果

[8 区域来源窗口复核](../japanese-source-matching/send-out-review.json)全部通过：2 项派出各保留 7 个来源及双打源的两个行号，6 项换入预告排除上一行被吞进名字的错误解释。类别＋姓名和完整联机姓名显示同一个训练家标签时，当前行动含义可以一致；不强选脚本、单双打或实际物种。只替换明确审过的源段／行窗口，完整双打两句和清屏后的问题继续保持通用假设。详见 [来源窗口报告](../japanese-source-matching/README.md#单／双打来源窗口与当前含义)。这是非盲模型源文核对，没有新增原生脚本执行、中文或实机验收。

原先 8 个普通升降和 24 个招式消息，**32／32** 均按单独冻结的原始日文、预期来源、当前名字和显示含义通过。8 项普通升降均保留两个对应源记录；未通过选择首个来源掩盖歧义。

本轮答案从当前可见日文及直接源记录编写并绑定哈希，不从匹配输出自动生成；但实现和复核为同一模型，**非盲测、非独立人员或人工验收**。它只证明这 32 项，不代表全游戏来源准确率。

30 项战斗专用检查包含原有能力、招式、经验值和派出边界，并增加 9 项观察消息复核、数值与有限词条反例及界面类型过滤。原来源匹配检查与中文工具检查另行保留。

同一原 769 跨度中，完整组成候选证据为 **766／769**；原 600 个命中无退化，仍缺 3 项均为未完整片段。当前 1,133 个字段／文字单元与历史中文单元不能互换。旧模型中文包、答案及 25／770、770／770 门槛已[撤回归档](../../archive/model-translations/README.md)。当前 [S6 原译文来源检查](../s6-acceptance/README.md)不代替中文语义验收，本来源入口继续不发布中文。

## 使用与重现

运行、查询和已有数据回归需要 Node.js 22+。普通使用不读取 ROM，不需要 Python、Capstone 或原生捕获组件。

```powershell
# 源码缓存和已核验的日版证据齐备后，离线重建模板。
node tools/build_battle_source_templates.mjs

# 使用同一批实际OCR重跑来源和战斗含义检查。
node tools/evaluate_source_matching.mjs
node tools/audit_source_bindings.mjs
node tools/test_source_matching.mjs
node tools/test_battle_source_matching.mjs

# 批量请求中保留实际换行和检测类型。
node tools/resolve_japanese.mjs --input requests.json --out resolved.json
```

输入示例：

```json
[
  {"japanese":"カイオーガの\nとくこうが あがった！","typeCandidates":["battle_message"]},
  {"japanese":"あいての サマヨールの\nれいとうビーム！","typeCandidates":["battle_message"]}
]
```

重新验证日版指令需要本地两份固定 ROM、已恢复且哈希匹配的源码及 Capstone 5.0.7：

```powershell
python tools/verify_battle_printing.py
python tools/verify_experience_printing.py
node tools/build_battle_source_templates.mjs
```

`freeze_battle_source_review.mjs` 只供首次建立独立存放的来源／显示含义基线，拒绝覆盖不同答案；日常回归读取已经冻结的文件。后续仍须核定其余来源语义、名字约束和组合单元，完成中文审核与 S7 集成。
