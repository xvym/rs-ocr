# 日文 OCR 离线开发基线

状态：S2 已建立可运行工程，S3 尚未通过。版本 `0.1.0`。以下为静态截图开发回归，不是实机、实时或最终产品验收。

## 已实现

- Java 21 图片入口：PNG、目录批处理、显式视口和两组截图配置，输出 240×160 归一化图、区域、原始日文、候选字符、像素距离和未识别位置。
- 直接从固定日版红宝石／蓝宝石提取四套字体、组合标记、预绘制标题、23 类属性／华丽徽标、五类背包分类和 SEL 标记。原生资产逐字节跨 ROM 核对，运行时不读取 ROM。
- 51 个现有区域键的检测与文字配置。标准框分别检查角部，避免把大框内的留白误当成小框；同形框保留用途候选。摘要页使用原生标题核对上下文，树果说明另核对原生页头图案。
- 字形保持未知标记 `�` 和全部相同候选，不读取词库、中文语料或测试答案补字。像素相同的 `へ／ヘ` 和 `0／O` 使用首个规范输出，同时保留候选；验收用等价规则仍是提案。
- 对已检测上层框覆盖的列表固定特征扣除后重试定位。文字是否完整的边界仍有未解决项，见下表，不能据此宣称 R18 全部实现。

## 运行

开发构建需要 JDK 21+、Maven 3.9。运行 JAR 只需要 Java 21+，不需要 Python、ROM、截图标注、上游源码、JavaFX、捕获组件或网络。当前是开发入口，尚不是 R16 的自带运行时发行包。

```powershell
.\build.ps1
.\run-offline.ps1 -Image 'gba_testcase/Screenshot 2026-10-31 15-38-28.png' -Profile gba-5x -Out 'reports/ocr-development/result.json'
.\run-offline.ps1 -Directory ngc_testcase -Profile ngc-capture -Out 'reports/ocr-development/ngc-raw.json'
```

`JAVA_HOME` 需指向 JDK 21+；两个脚本都接受 `-JavaHome`。构建脚本另接受 `-Offline` 和 `-MavenRepository`，不改全局 Java/Maven 设置。

| 图像配置 | 尺寸约束 | 采样视口 | 颜色增益 |
| --- | --- | --- | --- |
| `native` | 240×160 | 全图 | 0.984 |
| `gba-5x` | 1200×800 | `[0,0,1200,800]`，每逻辑像素中心采样 | 0.984 |
| `ngc-capture` | 1600×1200 | `[212,200,1168,800]`，每逻辑像素中心采样 | 0.82 |

NGC 的 1168 宽度是本次字形和固定特征校准结果，区别于旧人工目录的近似 1172 宽度。没有修改原目录或候选标注中的几何记录。配置只适用于现有图像条件，不证明 `gba_testcase` 的真实来源是 NDS，也不自动证明两作或其他尺寸／滤镜兼容。

自定义视口使用 `-Viewport 'x,y,width,height'`。直接运行 JAR 可用 `--color-gain` 显式设置颜色增益，`--normalized <目录>` 导出归一化图。视口越界、未知配置、尺寸不符和无效图片明确报错，不退回猜测位置。

## 重建运行资源

Python 仅用于开发资源提取与比较。依赖版本见 [requirements-dev.txt](../../tools/requirements-dev.txt)。按 Spec 固定版本恢复两份日版 ROM 与本地 pokeruby 源码后：

```powershell
python tools/extract_fonts.py
python tools/extract_labels.py
python tools/extract_sprites.py
python tools/build_regions.py
.\build.ps1
```

- [字体提取清单](font-extraction.json)：两作 ROM 哈希、逐字节一致的字体块、日版 u32 映射表、组合标记和资源哈希。美版 PNG／字符表用于查找和转写提案；字形从两份日版 ROM 回读，未套用美版地址。
- [固定标签提取清单](label-extraction.json)、[徽标／分类提取清单](sprite-extraction.json)：原生资产位置、跨版本一致性及模板哈希。日本版背包分类是 u8 顶部 tile 表、下半为顶部索引加 16；不使用美版 u16 标签表。
- [区域编译器](../../tools/build_regions.py)：从已核查特征去除截图编号、文件名、样本列表和用途说明，只输出运行所需几何、颜色、固定像素及文字排版。选择招式时会重涂 y=32 的原生上边缘，新增选择状态掩码忽略该动态行，保留两侧与底部证据。

## 比对与验证边界

```powershell
python tools/evaluate_ocr.py --results reports/ocr-development/gba-raw.json reports/ocr-development/ngc-raw.json
python tools/check_development.py
```

比较程序单独读取候选答案，将已检测区域按用途候选和几何关联到标注。识别器没有接收逐图 ROI、目标文字、截图编号、图片哈希索引或标注排除名单的接口。输入身份哈希仅写入诊断并用于测试可追溯性，不用于查询文本。

构建执行 10 项回归检查，覆盖两组真实图片、未知字符、框边被盖但完整列表保留、恢复窗口后的隐藏框、不残留上一帧、负样本、无效视口、徽标及 PP、选择招式的扩展框、PC 与其他白色页面的区分。另用复制到独立目录的 JAR 和重命名图片核查离线资源边界，结果见 [checks.json](checks.json)。这些检查不替代 S3 独立答案冻结，也不替代真实窗口遮挡捕获或时序验收。
